# Security — checklist tracker

This app **exposes a shell over the network.** `PLAN.md §5` is non-negotiable.
Any change touching auth, command execution, or the transport gets extra scrutiny
(`CLAUDE.md`). Transport is now Tailscale ([ADR 0005](decisions/0005-tailscale-transport.md)),
not a public tunnel — the daemon is never on the public internet. Track each item
here as it lands.

## Notes

- Transport boundary is the **tailnet**: only devices the owner added (and a
  Tailscale ACL permits) can resolve `<machine>.<tailnet>.ts.net` or reach the
  daemon. The bearer token (#2) is a second, app-level layer on top.
- **Spikes are unauthenticated** (`/pty/:id`, `/session/:id` in `serve-pty.ts`
  have no token check) and bind localhost only. **Do not `tailscale serve` a
  spike.** The authenticated M2 session endpoints replace it.
- The PTY engine is the highest-risk surface — it's an interactive shell. Item 7
  (scoping) and item 5 (audit) matter most there.
- **Claude tool permissions default to auto-allow** (proposal 18,
  [claude-ws.md](protocols/claude-ws.md#permissions-securitymd--highest-scrutiny)):
  tool calls execute without a per-call phone tap. Every auto-approval is
  audited (`permission.auto_allow`); the app's settings toggle (or an
  `auto_allow {on:false}` frame) restores the interactive gate per session.
